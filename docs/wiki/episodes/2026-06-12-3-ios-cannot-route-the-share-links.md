# Episode: iOS cannot route the share links it mints

## Prior State

iOS's `onOpenURL` handler only processed nip46 signer callbacks and share-extension handoffs — share links (nevent/nprofile/naddr) generated by the app itself were never routed when opened back on the same device.

## Trigger

Android deep-link implementation surfaced that `HighlighterNmpApp.decodeNostrEntity()` already existed in the core and could parse bech32 entities, revealing iOS had the capability but never wired it.

## Decision

Added `ShareLinkRouter.swift` to iOS with universal-link entitlements and `onOpenURL` handling that decodes nevent→`OpenComments`, nprofile→`OpenProfile`, and naddr (TODO: no single dispatch target yet). Android became the reference implementation for deep-link routing.

## Consequences

- iOS now routes its own share links end-to-end
- Android is the first platform with verified share-link consumption
- naddr deep links remain a TODO on both platforms (no `OpenArticleReader` dispatch yet)
- App Links require server-side `assetlinks.json` on beta.highlighter.com to activate `autoVerify`

## Open Tail

- Deploy assetlinks.json / AASA for verified universal links
- Add OpenArticleReader action for naddr deep links
