# Android Home Feed

## Home Feed

The home feed uses a LazyColumn with per-item keys (item.stableId) via a LazyListScope extension (homeFeedItems), not a single eager Column that composes all cards at once; the HighlightsTab previously hosted HomeFeedPanel as a single LazyColumn item { HomeFeedPanel(...) } which composed all 140+ cards eagerly, and now calls homeFeedItems directly inside the LazyColumn. The root cause of severe jank was rendering all ~140 cards eagerly in a plain Column with no virtualization; the LazyColumn conversion caps worst-case frame skips at ~36 frames (down from 100–379), confirming eager composition was the dominant cause. The home feed no longer silently truncates items at 8; the .take(8) cap was removed and the feed renders all items via an unbounded forEach, showing a distinct 'Syncing highlights…' loading state (testTag 'feed_loading') with a CircularProgressIndicator while syncing rather than masking a populated feed with 'Loading highlights'; a separate 'No highlights yet' empty state is shown when the feed is genuinely empty after loading completes. Feed cards display hydrated author avatars, names, and cover art by dispatching RequestProfile, RequestWebMetadata, RequestIsbnPreview, and RequestArticle actions per card via LaunchedEffect keyed by the relevant pubkey/ISBN/URL to resolve author profiles, ISBN previews, and web metadata, matching iOS .task(id:) semantics; each LaunchedEffect fires exactly once per unique key value, and each dispatch guards against re-dispatching by checking whether the datum already exists in LocalProfiles, LocalIsbnPreviews, or LocalWebMetadata before firing to prevent redundant re-requests for already-hydrated data. Core-side set_toast calls for three benign per-card lookup failures (ISBN preview not found, web metadata not found, profile subscription failed) are replaced with tracing::debug! logging, fixing the persistent 'not found' toast on both Android and iOS. LocalIsbnPreviews composition local provides state.isbnPreviews throughout the Compose tree (wired in the root CompositionLocalProvider alongside LocalProfiles and LocalWebMetadata to avoid prop drilling), and a previewForIsbn(isbn) extension on List<HighlighterIsbnPreview> resolves ISBN preview data for feed cards. Feed cards display resolved author avatar/name (via AvatarImage + LocalProfiles) and cover art (via RemoteImage + LocalWebMetadata/LocalIsbnPreviews), reusing existing components from CommentsPanel and RemoteImage; feed card author byline rows are independently clickable and dispatch OpenProfile(pubkeyHex) for highlight leads and read-item authors, consuming the tap so it does not fall through to the card's article-reader action. Tapping a highlight feed card opens a local Highlight Detail screen (via onOpenDetail callback, backed by selectedHighlight state in HighlightsTab) rather than dispatching OpenArticleReader; the detail shows the quote, tappable author byline (→ OpenProfile), a comment action (→ OpenComments with rootTagName='e', rootKind=9802), share via Android system sheet (Intent.ACTION_SEND), and optional bookmark (ToggleArticleBookmark for 30023 article-backed highlights); reading cards still dispatch OpenArticleReader directly. ShareHighlightRepost (repost to a room) is omitted because Android has no room-picker sheet; the system share sheet fills the affordance instead. Manual Refresh OutlinedButtons were removed from all screens (feed, rooms explorer, room detail/comments, reader, profile, bookmarks, media settings, feedback, and room invite); on-appear DisposableEffect Open* dispatches remain for live data loading, and PullToRefreshBox swipe-to-refresh gestures were intentionally kept—the MainScaffold HighlightsTab uses PullToRefreshBox with onRefresh dispatching RefreshHomeFeed, and RoomsTab uses PullToRefreshBox with onRefresh dispatching RefreshRoomExplorer. The ToastBanner (driven by state.toast) is repositioned below the status bar and TopAppBar using top padding = WindowInsets.statusBars + 64.dp + 8.dp to prevent it from overlapping the header. An auto-expire LaunchedEffect keyed on each toast object dispatches ClearToast after a 4-second delay, so any remaining toasts dismiss automatically. HighlighterViewModel.state is sampled at 16ms intervals via a lazy property applying .sample(16.milliseconds).stateIn(viewModelScope, SharingStarted.Eagerly, _state.value) to coalesce burst emissions to approximately one recomposition per frame, and spurious OS calls in onState (syncNetworkCallback on every emit) are guarded to only fire when wifiOnlyEnabled actually changes. HomeFeedPanel's debug log of feed.items is guarded by Log.isLoggable to skip the joinToString allocation in production. After the LazyColumn conversion, janky frames dropped from ~72% to ~48%, confirming the eager composition was the dominant cause (residual jank attributed to per-card image decode cost). The Android home feed populates with real highlight/article cards when logged in with an account that follows active highlighters, confirming the render path is correct; the earlier emptiness was caused by being in an unauthenticated state (no follows, onboarding not completed), not a Compose rendering or mapping bug, and the diagnosis is documented at Plans/feed-empty-fix.md and Plans/responsiveness-and-toast-fix.md. Feed card hydration (author avatars, names, cover art, metadata) is verified working at iOS visual parity, and the header/banner overlap fix is verified: header elements (title, connection status, settings) are fully visible, no longer occluded by toast banners.
